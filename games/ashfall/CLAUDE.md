# 잿불의 회랑 (ashfall)

핵앤슬래시 로그라이크. HTML5 Canvas 2D + 순수 ES 모듈.
**빌드 도구 없음 · 런타임 의존성 0개.** 자세한 설계는 `README.md`.

## 실행 / 검증

```bash
npm run serve          # http://localhost:8123 — 고치고 새로고침하면 끝
npm test               # 단위 66 + 헤드리스 런 + 밸런스 스윕
npm run build          # dist/ 단일 HTML (tools/build.mjs)
npm run test:build     # 번들 생성 + file:// 로드 검증
npm run test:browser   # Playwright 41개 (데스크톱 + 모바일 터치)
```

브라우저 테스트만 Playwright가 필요하다: `npm i -D playwright && npx playwright install chromium`.

**코드를 바꿨으면 `npm test`는 반드시, 렌더/UI/입력을 건드렸으면 `npm run test:browser`까지 돌린다.**
`src/` 를 바꾼 뒤 `dist/` 를 다시 만들지 않으면 배포본이 낡은 채로 남는다.

## 깨지 말아야 할 규칙

1. **`sim/` 은 DOM·캔버스·오디오를 모른다.** 그래서 node에서 런 전체를 헤드리스로 돌릴 수 있고,
   봇 측정이 가능하다. `sim/` 안에서 `document`·`window`·`Audio`를 쓰면 이 능력이 통째로 죽는다.
2. **sim은 "무슨 일이 일어났는지"만 `EventBus`로 알린다.** 어떻게 보이고 들릴지는 `render/`·`audio/`가 정한다.
   단방향이다 — `render/`가 `sim/`의 상태를 바꾸지 않는다.
3. **권능(boon)은 `loadout`으로 컴파일된다.** 보유 목록 → 스탯 + 훅 배열. 전투 루프는 훅만 호출한다.
   새 권능은 `data/boons.js`에 데이터로 추가하고, 필요하면 기존 훅에 붙인다.
   훅을 새로 파야 한다면 그 자체가 설계 판단이니 이유를 남긴다.
4. **UI 버튼은 게임 규칙을 갖지 않는다.** `ui/screens.js`는 `main.js`의 컨트롤러만 호출한다.
5. **시뮬레이션은 시드 RNG로 결정론적이다.** `Math.random()` 금지 — `world.rng`를 쓴다.
   같은 시드가 같은 런을 만들지 않으면 밸런스 측정이 전부 무의미해진다.
6. **수치는 코드에 박지 않는다.** 전부 `src/data/`. 특히 난이도는 `data/balance.js`의 `TUNING` 하나로 조절한다
   (`BOSS_HP` / `BOSS_HP_PER_DIFF` / `BOSS_DMG` / `ROOM_BUDGET` / `ENEMY_DMG`).
   개별 적·보스 데이터를 직접 만지는 건 마지막 수단이다.
7. **세이브 호환.** `data/balance.js`의 `SAVE_VERSION`과 `core/save.js`의 마이그레이션.
   저장 구조를 바꾸면 버전을 올리고 마이그레이션을 쓴다. 기존 세이브를 이유 없이 깨지 않는다.

## 밸런스는 감이 아니라 측정으로 정한다

이 프로젝트의 모든 밸런스 값은 봇 시뮬레이션 실측으로 확정됐다. 숫자를 바꿨으면 근거를 뽑는다.

```bash
node tests/sweep.mjs           # 승률 / 평균 도달 방 / 사망 지점
node tests/necro-branches.mjs  # 분기별 소환수 구성·피해 출처·경직 (REPS=12 로 표본 확대)
node tests/weapon-report.mjs   # 이론 DPS vs 실전 DPS — 차이가 크면 "약한" 게 아니라 "칠 기회가 없는" 것
node tests/touch-report.mjs    # 폰 세로 엄지 모사 입력 — 명중률·조준 오차·분당 피격
```

현재 기준선(강령장, 시드 24개): 승률 37% · 보스전 18/31/33초 · 방 13초 · 런 264초(봇).
**사망 15회 중 12회가 보스방** — 잡몹 방은 통과 구간, 보스가 관문인 것이 이 곡선의 핵심이다.
잡몹 방에서 죽기 시작하면 밸런스가 아니라 메커니즘이 깨진 것이다.

측정 결과가 이상하면 **게임보다 계측기를 먼저 의심할 것.** (거인 분기가 0/12로 나왔던 적이 있는데,
원인은 메커니즘이 아니라 그 분기만 소환수 지속시간 권능과 짝지어지지 않은 테스트 조합이었다.)

## 알려진 미해결 문제

- 방 클리어 HP가 런 내내 85~90%로 평평하다. 목표는 50~70%로 내려가는 소모 곡선인데,
  회복량 손잡이로는 안 내려간다 — 봇의 피격 빈도(런당 33회)가 낮아서다.
  회복이 아니라 **잡몹 방의 압박** 쪽 설계 문제.
- 거인 분기가 6/12로 가장 약하고 분당 처치도 82로 가장 낮다.
- 브라우저 테스트 중 전투 결과에 의존하는 항목 하나가 간헐적으로 실패한다. 재실행하면 통과한다.
