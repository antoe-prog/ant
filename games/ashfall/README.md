# 잿불의 회랑 (Ashfall)

핵앤슬래시 로그라이크. 한 판 **10~20분**, 매 판 다른 빌드.
빌드 도구 없이 브라우저에서 바로 돌아가는 순수 ES 모듈 + Canvas 2D 프로젝트다.

```
cd games/ashfall
node tools/serve.mjs        # http://localhost:8123  (개발)
node tools/build.mjs        # dist/ashfall.html — 단일 파일, 어디서든 열림
```

빌드 도구·의존성 없이 브라우저에서 바로 돌아간다.
`tools/build.mjs` 는 26개 모듈을 의존성 순서대로 묶어 **파일 하나**로 만든다
(공유해서 바로 플레이할 때 쓴다). 순환 import 와 번들 문법 오류는 빌드 시점에
즉시 실패시킨다 — 잘못된 코드가 브라우저까지 가지 않도록.
`node tests/build-check.mjs` 가 그 산출물을 `file://` 로 열어 실제로 플레이되는지 검증한다.

## 1. 무엇을 만들었는가

**Core Loop**

```
무기 선택 → 방 진입 → 전투(이동/대시/콤보/특수기)
   → 전멸 → 문 3개 중 선택(보상·위험을 미리 보고 결정)
   → 권능 획득(빌드 성장) → 다음 방 …
   → 구역 보스 → 다음 구역 → 최종 보스 → 승리/사망
   → 잿가루로 영구 강화 → 다음 런
```

- 구역 3개 × (전투 4방 + 보스 1방) = **15방**
- 봇 기준 순수 전투 시간 3~6분, 실제 플레이(선택/읽기 포함) **12~18분**

**조작 (키보드·마우스)** — 이동 `WASD` · 조준 `마우스` · 공격 `좌클릭`/`J` ·
특수기 `우클릭`/`K` · 대시 `Space` · 소환수 명령 `F` · 일시정지 `Esc`

**조작 (터치)** — 왼쪽 화면 드래그로 이동(누른 자리가 스틱 원점) ·
오른쪽 화면 드래그로 조준하며 자동 공격 (짧게 톡 치면 가장 가까운 적 공격) ·
우하단 버튼으로 대시 / 특수기 / 명령

터치 감도는 **타이틀 → 조작 탭 → 터치 감도**, 또는 **플레이 중 일시정지 → 터치 감도**에서
언제든 바꿀 수 있다. 손 크기·그립·기기는 사람마다 다르므로 기본값은 정답이 아니다.

| 설정 | 뜻 |
|---|---|
| 스틱 반경 | 엄지를 최대로 꺾는 거리. 작을수록 조금만 움직여도 최대 속도 |
| 데드존 | 이 안의 움직임은 무시. 손떨림으로 캐릭터가 흔들리면 올린다 |
| 조준 보정 | 조준 방향이 적을 거의 향하면 그쪽으로 끌어당기는 강도 |
| 보정 범위 | 보정이 걸리는 각도. 넓히면 편하지만 원하는 적을 못 고를 수 있다 |
| 버튼 크기 | 대시·특수기·명령 버튼 배율 |
| 따라오는 스틱 | 엄지가 반경을 넘으면 원점이 따라온다 (스틱이 '끝까지 꺾인 채' 굳지 않게) |
| 톡 쳐서 공격 | 오른쪽을 짧게 치면 가장 가까운 적을 공격 |
| 왼손잡이 배치 | 이동/조준과 버튼 위치를 좌우 반전 |
| 진동 피드백 | 버튼 입력 시 진동 (지원 기기 한정) |

모든 행동 입력에 **0.18초 버퍼**가 있어 짧게 톡 누른 키가 프레임 사이에서 사라지지 않는다.

## 2. 재미의 축

### 무기 — 강령장

| 무기 | 콤보 | 정체성 | 특수기 |
|---|---|---|---|
| 강령장 | 3연격(느림) | 사거리가 길다. 눕힌 적의 **시체를 다시 일으킨다** | 망자 봉기 — 주변 시체를 해골 병사로 |

- 처치 시 30% 확률로 망령이 자동으로 일어난다
- 주변 시체 1구당 공격속도 +6% (최대 +36%) — 시체 위에서 싸우게 만드는 압력
- 후딜은 대시로 캔슬할 수 있다(공수 전환의 기본기)
- 단계별로 이동 가능 비율이 다르며(선딜/판정/후딜) 후딜에서 가장 많이 풀린다.
  "휘두르는 동안 발이 묶이는" 구간을 최소화하는 것이 이 장르의 기본 손맛이다

### 지휘 — 소환수는 자동 전투가 아니다

`F`(또는 터치 '명령' 버튼)로 조준 지점을 찍으면 군세가 그리로 몰려간다.

- 지정 반경 230 안의 적을 **최우선**으로 노린다 (가까운 적보다 우선)
- 명령 지속 3.6초 동안 소환수는 이동속도 +40%, 피해 +30%
- 쿨다운 6초, 소환수가 없으면 발동하지 않는다
- 공격 중에도 낼 수 있다 — 지휘는 내 행동을 끊지 않는다

덕분에 소환 빌드가 "알아서 싸우는 것을 구경하는" 빌드가 아니라
**어디를 언제 무너뜨릴지 고르는** 빌드가 된다.

### 사령술 — 시체가 전장의 자원이 된다

숫자를 올리는 빌드가 아니라 **전장의 구성을 바꾸는** 빌드다.

```
적 처치 → 그 자리에 시체가 남는다 (11초, 위치가 곧 자원)
  → 일으킨다: 망령/해골 병사/뼈 궁수가 내 편으로 싸운다
  → 해골 병사는 몸으로 적탄을 막는다 (진형이 생긴다)
  → 또는 터뜨린다: 시체 폭발로 즉발 광역
  → 또는 흡수한다: 체력·집중 회복
  → 적 '시체 술사'도 같은 시체를 노린다 → 자원 경쟁
```

- **시체**는 위치를 가진 소모성 자원이다. *어디서 싸웠는지*가 그대로 힘이 된다.
  강령장은 주변 시체 1구당 공격속도 +6%(최대 +36%) — 시체 위에서 싸우게 만드는 압력.
- **소환수 5종**

| 소환수 | 역할 |
|---|---|
| 망령 | 빠르게 달려들어 무는 근접. 처치·대시에서 자동으로 나온다 |
| 해골 병사 | 느리고 단단하며 **적탄을 몸으로 막는다** |
| 뼈 궁수 | 거리를 두고 뼈 화살을 쏜다 |
| 뼈 사냥개 | 아주 빠르고, 물면 **적의 행동을 끊는다**(경직). 피해는 낮다 |
| 해골 거인 | 크고 느리다. **광역으로 내리치고** 적탄을 막는다 |

- **사령술은 네 갈래로 갈라진다.** 전부 사이드그레이드다 — 세지는 게 아니라 역할이 바뀐다.

| 분기 | 권능 | 무엇이 바뀌는가 | 대가 |
|---|---|---|---|
| 군세 | 군세 | 약한 다수가 대신 싸운다 | — |
| 사냥개 | 사냥개 무리 | 망령이 사냥개로 바뀌어 적을 **붙잡아 둔다** | 피해가 낮다 |
| 거인 | 거인 결속 | 망자 봉기가 시체를 합쳐 **하나의 벽**을 세운다 | 수를 포기한다 |
| 폭렬 | 폭렬 결속 | 소환수가 지속 유닛이 아니라 **탄약**이 된다 | 지속시간 -40% |
| 역병 | 역병 | 소환수 타격이 화상·출혈을 남긴다 | 소환수 피해 -20% |

- **분기는 후반까지 이어진다.** 갈래마다 전용 합일이 하나씩 있다.

| 조건 | 합일 | 효과 |
|---|---|---|
| 사냥개 무리 + 서리 계열 | **서리 송곳니** | 사냥개가 물면 냉기. 빙결된 적을 물면 경직 + 추가 피해 |
| 거인 결속 + 재 계열 | **무너지는 거인** | 거인이 스러질 때 무너져 내린다. 합친 시체가 많을수록 크다 |
| 폭렬 결속 + 폭풍 계열 | **연쇄 폭렬** | 하나가 터지면 주변 소환수도 함께 터진다 |
| 역병 + 피 계열 | **역병의 피** | 화상+출혈로 죽은 적 자리에서 망령이 일어나고 회복 |

  분기 권능의 설명에 **무엇으로 이어지는지 미리 적혀 있다** —
  고르기 전에 알 수 없으면 설계 의도가 전달되지 않는다.
  합일 카드에는 무엇이 그것을 열었는지 조건이 표시된다.

  `node tests/necro-branches.mjs` 로 분기가 실제로 갈라지는지 측정할 수 있다.
  수치만 다르고 플레이가 같으면 분기가 아니다 — 아래는 측정 결과다.

| 분기 | 평균 소환수 | 주력 소환수 | 피해 출처 (소환수/폭발/직접) | 적 경직 시간 |
|---|---|---|---|---|
| 군세 | 44.2 | 망령 92% | 29 / **59** / 13 | 0% |
| 사냥개 | 30.9 | **사냥개 87%** | **43** / 37 / 20 | **26%** |
| 거인 | **15.3** | 망령 + 거인 | 28 / 41 / **31** | 0% |
| 폭렬 | 23.3 | 망령 92% | 18 / **70** / 12 | 0% |
| 역병 | 34.4 | 망령 85% | 25 / 43 / **32** | 0% |

  **소환수 수에는 제한이 없다.** 자연스러운 상한은 지속시간이 만든다 —
  소환 속도 × 지속시간이 곧 동시 존재 수다. 사령술을 최대로 갖추면
  평균 70마리, 최대 130마리까지 나온다.
  아군은 전부 **같은 민트색 링**을 달아 난전에서도 규칙 하나로 구분된다.

  수가 많아질 때를 대비한 처리:
  - 목표 재탐색을 0.15초 주기로만 하고 개체별로 시점을 분산 (매 프레임 전수 탐색 제거)
  - 접촉 판정은 '지금 쫓는 적'만 확인
  - 36마리를 넘으면 자동으로 단순하게 그린다(LOD) — 겹쳐서 안 보이는 디테일에 비용을 쓰지 않는다

  | | 최적화 전 | 최적화 후 |
  |---|---|---|
  | 시뮬 1틱 최악 (130마리) | 8.01ms | **5.09ms** |
  | 렌더 개체당 비용 | 0.09ms | **0.057ms** |
- **해골 군주(미니보스)** 와 **최종 보스의 격노 페이즈**가 전장의 시체를 되살린다.
  내가 시체를 아껴두면 보스가 그것을 쓴다 — 보스전에서도 시체 관리가 판단이 된다.
  (시체가 없으면 패턴이 헛돌지 않도록 직접 소환으로 대체된다)
- **적 시체 술사**가 전장의 시체를 되살린다. 길게 예고되므로
  *먼저 끊을지 / 시체를 먼저 치울지*를 고르게 된다. 되살아난 적은 다시 시체를
  남기지 않아 무한 고리가 생기지 않는다.
- **합일 권능** 4종이 사령술을 다른 계열과 잇는다 —
  화장(소환수가 죽으며 폭발), 빙결의 무덤(시체가 사라질 때 냉기 폭발),
  영혼 방전(소환수 타격이 연쇄 번개), 생명 착취(소환수 피해를 내 회복으로)

### 상태이상이 서로 맞물린다
| 상태 | 효과 |
|---|---|
| 화상 | 중첩 도트 |
| 냉기 | 둔화, 최대 중첩 시 **빙결** |
| 빙결 | 행동 불가 + **받는 피해 ×1.35** (권능 없이도 기본 보상) |
| 감전 | 연쇄 번개/피해 증폭의 연결점 |
| 출혈 | 중첩 도트, 냉기·폭풍 권능과 상호작용 |
| 경직 | 짧게 행동이 끊긴다 (무거운 타격의 보상, 상태이상 아님) |

플레이어도 디버프를 받는다 — 서리창 기병의 돌진은 **냉기(이동 둔화)**, 폭풍 감시자의 탄은 **감전(집중 회복 감소)**.

### 보스 3종
페이즈별로 패턴 풀·속도·쿨다운이 바뀐다. 몸통 접촉은 피해를 주지 않고 밀어낸다 —
**근접해서 때리는 것을 처벌하지 않고, 피해는 전부 예고된 패턴에서만 나온다.**

### 메타 진행
사망/클리어 시 **잿가루**를 얻어 영구 강화 7종(체력·피해·이동·방 회복·행운·대시 충전·부활)을 산다.
세이브는 버전 + 마이그레이션 + 손상 복구를 갖춘다.

## 3. 구조

```
src/
  core/     math rng events input touch save      ← 엔진 비의존 유틸
  data/     balance weapons enemies boons minions ← 모든 수치 (튜닝 지점)
  sim/      world player enemyAI boss combat loadout run minions
  render/   camera renderer vfx hud
  audio/    sfx
  ui/       screens (DOM 오버레이)
  main.js   부트스트랩 + 고정 타임스텝 루프
```

**권능이 sim 에 꽂히는 지점(훅)**

| 훅 | 시점 | 쓰는 권능 예 |
|---|---|---|
| `modifyDamage` | 피해 계산 직전 | 파쇄, 과전류, 광란 |
| `hit` / `kill` | 적중 / 처치 | 방전 각인, 번지는 불씨, 참수 |
| `attackStep` | 콤보의 특정 타가 나갈 때 | 검압, 지진 |
| `dashStart` / `dashTrail` / `dashEnd` | 대시 시작/경로/종료 | 한파의 자취, 작열 폭발 |
| `dashStrike` | 대시 강타가 적중 | 그림자 일격 |
| `special` | 특수기 사용 | 벼락 소환 |
| `hurt` | 피격 | 가시 갑주, 철벽 |
| `statusApplied` | 상태이상 부여 | 열충격 |
| `corpse` / `corpseExpire` | 시체 생성 / 자연 소멸 | 죽음의 손아귀, 빙결의 무덤 |
| `summon` / `minionDeath` | 소환수 등장 / 소멸 | 화장 |
| `tick` | 매 틱(밟고 지나가는 상호작용) | 시체 흡수 |

**희귀도 스케일링과 상한** — 권능 수치는 희귀도 × 레벨로 커지지만,
`caps` 가 지정된 키(확률·감소율)는 그 값을 넘지 않는다.
전설 3레벨에서 "확률 116%" 같은 무의미한 값이 나오지 않도록 하는 안전장치다.

**규칙**

1. `sim/` 은 DOM·캔버스·오디오를 전혀 모른다. 그래서 node 에서 런 전체를 돌릴 수 있다.
2. sim 은 **무슨 일이 일어났는지**만 `EventBus` 로 알린다. 어떻게 보이고 들릴지는 `render/`·`audio/` 가 정한다.
3. 권능은 `loadout` 으로 **컴파일**된다 — 보유 목록 → 스탯 + 훅 배열. 전투 루프는 훅만 호출한다.
4. UI 버튼은 게임 규칙을 갖지 않는다. `ui/screens.js` 는 `main.js` 의 컨트롤러만 호출한다.
5. 시뮬레이션은 시드 RNG로 결정론적이다(같은 시드 = 같은 런).

**책임 분리 요약**

```
입력 → intent → sim.step() → 상태 변화 + 이벤트
                                  ├→ vfx    (파티클/숫자/링)
                                  ├→ sfx    (WebAudio)
                                  ├→ hud    (상태 표시)
                                  └→ screens(선택 UI)
```

## 4. 밸런스 튜닝

수치는 전부 `src/data/` 에 있다. 코드를 고칠 필요가 없다.

| 파일 | 내용 |
|---|---|
| `balance.js` | 플레이어 스탯, 히트스톱/셰이크, 상태이상, 런 구조, 보상 가중치, 저주, 희귀도, 상점, 메타 강화 |
| `weapons.js` | 무기별 콤보 프레임(선딜/판정/후딜), 피해, 사거리, 각도, 넉백, 특수기 |
| `enemies.js` | 적 스탯·AI·예고 시간, 보스 페이즈/패턴, 구역별 적 풀과 스폰 예산 |
| `boons.js` | 권능 정의(수치 + 적용 함수 + 상한), 합일 권능 조건 |
| `minions.js` | 시체 지속시간/상한, 소환수 3종 스탯, 소환 규칙 |

바꾼 뒤에는 반드시:

```
node tests/run-all.mjs      # 단위 + 헤드리스 런 + 밸런스 스윕
```

`sweep.mjs` 는 봇으로 무기 × 시드를 돌려 **승률 / 평균 도달 방 / 사망 지점**을 뽑는다.
`weapon-report.mjs` 는 무기별 이론 DPS와 실전 DPS의 괴리를 보여준다 —
**둘의 차이가 크면 그 무기는 "숫자가 약한" 게 아니라 "칠 기회를 못 얻고 있다"**는 신호다.

현재 기준선 (시드 40개 × 무기 3종):

| 무기 | 봇 승률 | 평균 도달 방 |
|---|---|---|
| 강령장 | 63% | 13.1 |

무기가 하나가 된 지금, 이 승률이 곧 게임의 난이도다. 63%는 로그라이크치고 쉬운 편이고,
사령술 분기를 갖추면 분기별로 50~100%까지 올라간다.
난이도를 올리려면 `RUN.DIFFICULTY_PER_ROOM / DIFFICULTY_PER_BIOME` 를 조정한다.

사망 지점이 2구역~최종 보스(3-5)에 몰려 있으면 난이도 곡선이 건강한 상태다.
한 무기만 1구역에서 죽으면 밸런스가 아니라 **메커니즘**이 안 돌고 있는 것이다.

## 5. 테스트

```
node tests/run-all.mjs        # 단위 57 + 헤드리스 플레이 + 밸런스 스윕
node tests/weapon-report.mjs  # 무기 밸런스 실측 리포트
node tests/browser.mjs        # 브라우저 스모크 — 데스크톱 + 모바일 터치 + 설정
node tests/touch-report.mjs   # 터치 감도 실측 (엄지 모사 입력, 조건별 A/B)
node tests/necro-branches.mjs # 사령술 분기가 실제로 다른 플레이인지 측정
node tests/build-check.mjs    # 번들 산출물이 실제로 플레이되는지 검증
```

`touch-report.mjs` 는 **사람 엄지의 특성을 모사한 입력**으로 실제 브라우저에서 플레이시킨다.

- 떨림(jitter ±7px) — 엄지는 한 점을 정확히 유지하지 못한다
- 짧은 드래그(26~52px) — 엄지 가동 범위는 좁다
- 반응 지연 — 화면을 보고 손이 따라가는 데 시간이 걸린다

측정 지표는 **분당 처치 · 명중률 · 평균 조준 오차(°) · 분당 피격**.
`REPS=4 SECS=28 node tests/touch-report.mjs` 로 조준 보정 강도를 바꿔가며
통제 실험을 돌릴 수 있다. 감도를 "느낌"이 아니라 수치로 판단하기 위한 도구다.

조준 보정 기본값(0.55)은 이 실험으로 정했다 (조건당 4판 × 28초):

| 조건 | 조준 오차 | 명중률 | 분당 피격 |
|---|---|---|---|
| 보정 없음 | 18.0°±2.1 | 65% | 21.4 |
| **보정 0.55** | **11.8°±1.2** | **73%** | **19.1** |
| 보정 0.85 | 7.8°±3.1 | 68% | 25.8±8.1 |

보정을 세게 걸면 조준은 정확해지지만 **피격이 오히려 늘어난다** —
조준이 가까운 적에게 끌려가 원하는 위치를 잡지 못하기 때문이다.

참고: 같은 조건에서 키보드 플레이는 분당 피격 6~9회다.
**모바일은 구조적으로 2~3배 불리하다.** 아직 이 격차를 보정하지 않았다.

- `unit.mjs` (66항목) — RNG 결정론, 판정 수학, 데이터 무결성(모든 권능/보스 패턴 참조 검증),

  사령술 분기(소환수 종류 교체·거인 병합·폭렬 폭발·역병·거인 광역 강타),

## 6. 알려진 한계 / 다음 작업 후보

- 게임패드 미지원 (입력 계층은 intent 로 추상화되어 있어 추가는 간단)
- 아트/사운드 에셋 없음 — 전부 절차적 도형과 합성음
- 무기 1종 · 적 10종 · 소환수 5종 · 엘리트 접두사 6종 · 미니보스 4종 · 보스 3종 · 권능 53종 규모
- 무기가 하나뿐이라 빌드 분기가 권능에만 의존한다. 사령술 4갈래로 일부 회복했지만
  무기별 정체성이라는 축은 여전히 없다.
- 봇 승률 50~63%(분기 갖추면 더 오른다)는 로그라이크치고 쉽다. 난이도 재조정이 필요하다.
- 브라우저 테스트 중 전투 결과에 의존하는 항목 하나가 간헐적으로 실패한다
  (봇이 제한 시간 안에 적을 못 잡는 경우). 재실행하면 통과한다.
