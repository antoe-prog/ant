# 파이널 유도 멀티짐 최종 MVP 제품 설계서

작성일: 2026-06-13
상태: MVP v1.0 통합 기준
대상: 총괄 PM, 디자인, 프론트엔드, 백엔드, QA

## 1. 최종 의사결정 요약

파이널 유도 멀티짐 MVP는 랜딩페이지가 아니라, 유도장/멀티짐의 실제 운영을 처리하는 역할 기반 운영툴이다. 첫 릴리즈는 회원, 학부모, 코치, 대표, 총괄 어드민이 하나의 시스템에서 수업, 출석, 회원권/결제 상태, 공지, 지점 운영 현황, 권한/감사 로그를 처리하는 상태를 목표로 한다. 요청 기능은 현재 제품 범위에서 비활성화되어 화면 진입점과 카드가 노출되지 않는다.

최종 결정은 다음과 같다.

- MVP는 "멀티 지점 유도 체육관 운영 OS의 첫 버전"으로 정의한다.
- 랜딩페이지, 마케팅, 커뮤니티, 온라인 결제, 고급 분석은 MVP에서 제외한다.
- 결제는 PG 연동 없이 수기 결제 기록과 상태 관리로 시작한다.
- 코치는 결제 금액을 보지 않고 회원권 활성/만료 여부만 본다.
- 모든 핵심 운영 데이터는 지점 단위로 격리한다.
- 보호자 접근은 단순 RBAC가 아니라 보호자-자녀 관계 검증을 함께 통과해야 한다.
- 출석, 결제, 권한 변경, 개인정보/CSV 조회는 감사 로그 대상이다.
- 코치 출석 화면은 모바일/태블릿 현장 사용성을 최우선으로 한다.
- 대표/총괄 어드민 화면은 데스크톱의 표, 지표, 필터, 감사 가능성을 최우선으로 한다.

- 웨어러블/체성분 기기 연동

- 재고/용품 판매, 프랜차이즈 계약 관리

## 4. 역할과 권한 모델

제품에서 보이는 역할은 5개로 고정한다.

| 제품 역할 | 권장 코드 | 백엔드 RBAC 코드 | 데이터 범위 | 핵심 권한 |
| --- | --- | --- | --- | --- |
| 회원 | `member` | `member` | 본인 | 일정, 출석, 회원권/결제 상태, 공지 |
| 학부모 | `guardian` | `guardian` | 연결된 자녀 | 자녀 일정/출석/결제 상태, 공지 |
| 코치 | `coach` | `coach` | 담당 지점/수업 | 오늘 수업, 출석 체크, 제한 회원 정보, 수업 메모 |
| 대표 | `owner` | `branch_owner` | 배정된 지점 | 회원/수업/결제/코치/공지/리포트 관리 |
| 총괄 어드민 | `admin` | `super_admin` | 전체 시스템 | 지점, 사용자, 권한, 설정, 감사 로그 |

권한 판정은 항상 다음 순서로 한다.

1. 인증된 사용자 확인
2. 활성 역할과 권한 확인
3. 요청 리소스의 실제 `branch_id` 서버 계산
4. 지점 역할이면 사용자 역할의 `branch_id`와 리소스 `branch_id` 일치 확인
5. 학부모이면 활성 보호자-자녀 관계 확인
6. 회원이면 본인 리소스 확인
7. 코치이면 담당 수업/담당 회원 조건 추가 확인
8. 민감 조회와 쓰기 작업은 감사 로그 기록

## 5. 최종 IA와 URL 정책

최종 IA는 "역할별 홈 + 모듈 중심 URL"을 기준으로 한다. 역할마다 완전히 다른 URL 트리를 복제하지 않고, 같은 모듈 URL에서 역할과 권한에 따라 보이는 데이터와 액션을 다르게 한다. 단, 대표/총괄 어드민처럼 전용 관리 모듈이 필요한 경우 하위 네임스페이스를 둔다.

현재 구현은 `/app/dashboard`, `/app/classes`, `/app/members`, `/app/payments`, `/app/notices`를 기준 라우트로 사용한다. 기존 `/dashboard`, `/classes`, `/members`, `/payments`, `/notices` 주소는 호환 리다이렉트로만 남긴다. 삭제된 요청 기능의 `/app/requests`와 `/requests`는 제공하지 않는다.

### 공통/인증

| URL | 목적 |
| --- | --- |
| `/login` | 공통 로그인 |
| `/reset-password` | 비밀번호 재설정 |
| `/invite/:token` | 코치/대표/어드민 초대 가입 |
| `/select-role` | 복수 역할 사용자 역할 선택 |
| `/app/account` | 내 계정 |
| `/app/notifications` | 알림/공지 수신함 |

### MVP 핵심 모듈

| URL | 노출 역할 | 목적 |
| --- | --- | --- |
| `/app/dashboard` | 전체 | 역할별 홈 |
| `/app/classes` | 전체 | 수업/시간표/출석 조회, 코치 이상 출석 처리 |
| `/app/members` | 전체 | 본인/자녀/담당 회원/지점 회원 관리 |
| `/app/payments` | 회원, 학부모, 대표, 어드민 | 회원권/결제 상태, 미납/만료 관리 |
| `/app/notices` | 전체 | 공지 목록, 읽음 상태, 공지 작성 |

### 대표/어드민 전용

| URL | 노출 역할 | 목적 |
| --- | --- | --- |
| `/app/owner/branches` | 대표 | 배정 지점 관리 |
| `/app/owner/reports` | 대표 | 지점별 운영 리포트, CSV |
| `/app/admin/branches` | 총괄 어드민 | 전체 지점 관리 |
| `/app/admin/users` | 총괄 어드민 | 전체 사용자 관리 |
| `/app/admin/roles` | 총괄 어드민 | 역할/권한 관리 |
| `/app/admin/audit-logs` | 총괄 어드민 | 감사 로그 조회 |
| `/app/admin/settings` | 총괄 어드민 | 시스템 설정, 파일럿 준비 증빙 |

## 6. 핵심 사용자 플로우

| 플로우 | 단계 | 성공 기준 |
| --- | --- | --- |
| 지점 개설 | 어드민 로그인 -> 지점 생성 -> 대표 초대/배정 | 대표가 해당 지점 데이터만 접근 |
| 운영 세팅 | 대표 로그인 -> 코치 초대 -> 수업/반 생성 -> 회원 등록 -> 회원권 등록 | 오늘 수업 명단이 생성됨 |
| 출석 체크 | 코치 로그인 -> 오늘 수업 선택 -> 명단 확인 -> 출석 상태 변경 -> 저장 | 30초 이내 처리, 변경 로그 기록 |
| 학부모 확인 | 학부모 로그인 -> 자녀 선택 -> 오늘 수업/출석/공지/결제 상태 확인 | 연결된 자녀 데이터만 노출 |
| 요청 기능 | `/app/requests`, `/requests`, `/api/v1/requests*` 직접 접근 | 라우트/API 미제공, 404 |
| 결제 상태 관리 | 대표 회원권 등록 -> 수기 결제/미납/환불 기록 -> 회원/학부모 조회 | 코치는 금액 미노출 |
| 권한 변경 | 어드민 사용자 선택 -> 역할 변경 -> 위험 권한 확인 -> 저장 -> 감사 로그 | self-lockout 방지 |

## 7. 5개 핵심 화면 최종 설계

### 7.1 회원 대시보드

목적: 회원이 오늘 수업, 출석, 회원권 상태, 공지를 빠르게 확인한다.

필수 구성:

- 상단: 인사말, 소속 지점, 이용권 상태 배지, 알림
- 카드: 다음 수업, 이번 달 출석, 회원권 만료/미납, 최근 공지
- 리스트: 예정 수업, 최근 출석, 공지
- 액션: 수업 보기, 출석 내역 보기, 문의
- 빈 상태: 등록 수업 없음, 출석 내역 없음, 공지 없음
- 오류 상태: 수업/회원권 데이터 로드 실패, 권한 없음
- 모바일: 단일 컬럼, 다음 수업 카드 최상단, 하단 탭

### 7.2 학부모 자녀 관리 대시보드

목적: 여러 자녀의 수업/출석/결제/공지 상태를 한 화면에서 비교한다.

필수 구성:

- 상단: 자녀 선택 탭, 선택 자녀 프로필, 소속 지점
- 카드: 오늘 출석, 다음 수업, 이번 달 출석률, 결제/회원권 상태, 코치 알림
- 탭: 출석 기록, 진도/메모, 공지, 결제 상태, 보호자 정보
- 액션: 자녀 전환, 상담 요청, 결제 상태 보기
- 빈 상태: 연결 자녀 없음, 자녀 수업 없음
- 오류 상태: 보호자 관계 확인 실패, 자녀 데이터 로드 실패
- 모바일: 자녀 선택 가로 스크롤, 선택 자녀 기준 카드만 표시

### 7.3 코치 오늘 수업/출석 체크

목적: 현장에서 수업 명단을 보고 빠르게 출석을 처리한다.

필수 구성:

- 상단: 오늘 날짜, 지점, 수업 전환 세그먼트, 저장 상태
- 카드: 현재 수업 정보, 정원, 출석/지각/결석/사유 카운터
- 명단: 회원명, 띠/레벨, 나이대, 주의사항, 회원권 상태 요약, 출석 상태 버튼
- 액션: 전체 출석, 상태 변경, 메모, 저장, 저장 후 알림
- 빈 상태: 오늘 수업 없음, 수강생 없음
- 오류 상태: 네트워크 실패, 저장 충돌, 다른 코치 수정
- 모바일: 44px 이상 터치 영역, 하단 sticky 저장 바, 오프라인/미동기화 배지

### 7.4 대표 전체 지점 대시보드

목적: 지점별 운영 상태, 매출, 회원 증감, 출석률, 위험 지표를 빠르게 감지한다.

필수 구성:

- 상단: 기간 필터, 지점 필터, CSV 내보내기, 마지막 업데이트
- KPI: 월 매출, 활성 회원, 신규, 퇴관/휴면, 출석률, 미납/만료 예정
- 차트: 매출 추이, 출석률 추이, 신규/이탈 추이
- 테이블: 지점명, 회원 수, 매출, 출석률, 신규, 이탈, 전월 대비
- 알림: 미납 증가, 출석률 하락, 상담 전환 저조, 정원 초과 위험
- 모바일: 조회 중심, 카드 요약 우선, 표는 카드형 또는 가로 스크롤

### 7.5 총괄 어드민 권한 관리

목적: 사용자 역할과 권한을 안전하게 부여, 변경, 감사한다.

필수 구성:

- 상단: 사용자 검색, 역할/사용자/권한 매트릭스/감사 로그 탭
- 카드: 시스템 역할 수, 커스텀 역할 수, 관리 권한 보유자, 대기 초대
- 좌측: 사용자/역할 목록
- 우측: 선택 역할의 권한 매트릭스
- 매트릭스: 리소스 x 보기/생성/수정/삭제/승인
- 액션: 역할 생성, 복제, 사용자 초대, 권한 저장, 변경 취소
- 보호장치: 시스템 기본 역할 직접 수정 제한, self-lockout 방지, 위험 권한 확인 모달
- 감사: 변경 전/후 diff, 수행자, 시간, 대상, 사유 기록
- 모바일: 조회/긴급 비활성화 중심, 매트릭스 편집은 데스크톱 권장

## 8. 디자인 시스템 최종 기준

디자인 시스템의 단일 기준 파일은 `docs/design-system.md`와 `design-tokens/final-judo.tokens.json`이다.

적용 원칙:

- 한국형 SaaS 운영툴 톤을 유지한다.
- 카드 반경은 8px 이하를 기본으로 한다.
- 페이지 섹션을 카드처럼 중첩하지 않는다.
- 회원/학부모/코치는 모바일 사용성을 우선하고, 대표/어드민은 데스크톱 표/필터를 우선한다.
- 출석, 결제, 권한, 저장 상태는 색상만으로 구분하지 않고 텍스트와 아이콘을 함께 쓴다.
- 숫자 지표는 tabular number를 사용한다.
- 모바일 터치 액션은 최소 44px, 코치 출석 주요 버튼은 48px 이상으로 둔다.

필수 컴포넌트:

- 기초: `Button`, `IconButton`, `Input`, `Select`, `Checkbox`, `Switch`, `Tabs`, `SegmentedControl`, `Badge`, `Card`, `DataTable`, `Modal`, `Drawer`, `Toast`, `EmptyState`, `ErrorState`, `Skeleton`
- 레이아웃: `AppShell`, `SidebarNav`, `BottomTabNav`, `TopBar`, `PageHeader`, `FilterBar`, `RoleSwitcher`, `BranchSelector`, `PermissionGate`, `ProtectedRoute`
- 도메인: `KpiCard`, `BranchComparisonTable`, `AlertPanel`, `NextClassCard`, `ChildSwitcher`, `AttendanceRoster`, `AttendanceStatusButton`, `OfflineSaveBanner`, `PermissionMatrix`, `UserRoleTable`, `AuditLogDrawer`

## 9. 백엔드/DB 최종 기준

백엔드/DB의 단일 기준 파일은 `docs/BACKEND_DB_SCHEMA.md`다.

핵심 모델:

- `users`: 로그인 계정
- `roles`, `permissions`, `role_permissions`, `user_roles`: RBAC
- `branches`: 지점
- `members`: 실제 수련자
- `guardians`, `member_guardians`: 보호자와 자녀 관계
- `classes`, `class_sessions`, `enrollments`: 수업, 회차, 등록
- `attendance`: 출석 기록
- `notices`, `notice_targets`, `notice_reads`: 공지와 읽음 상태
- `counseling_notes`: 상담/주의 메모
- `memberships`, `payments`: 회원권과 수기 결제
- `audit_logs`: 감사 로그

최종 상태값 정리:

| 영역 | 최종 상태값 |
| --- | --- |
| 회원 | `trial`, `active`, `paused`, `withdrawn` |
| 출석 | `unchecked`, `present`, `late`, `absent`, `excused` |
| 수업 회차 | `scheduled`, `cancelled`, `completed` |
| 회원권 | `pending`, `active`, `expiring_soon`, `paused`, `expired`, `cancelled` |
| 결제 | `scheduled`, `paid`, `overdue`, `cancelled`, `refunded`, `partially_refunded` |
| 요청 | `pending`, `approved`, `rejected` |

현재 프론트엔드는 학부모 역할 코드를 `guardian`으로 정렬했다. 프로토타입 상태값도 `withdrawn`, `scheduled`, `expiringSoon`, `excused`를 쓰도록 정렬했다. 실제 DB/API 단계에서는 snake_case 값과 프론트 camelCase 값의 직렬화 정책을 확정해야 한다.

## 10. 충돌 정리

| 충돌 | 최종 결정 | 후속 작업 |
| --- | --- | --- |
| `학부모` 코드가 `parent`와 `guardian`으로 혼재 | 제품 라벨은 학부모, 도메인 코드는 `guardian` | 프론트 타입 `guardian` 적용 완료 |
| 대표/어드민 코드가 `owner/admin`과 `branch_owner/super_admin`으로 혼재 | UI는 `owner/admin`, RBAC 시스템 역할은 `branch_owner/super_admin` | 매핑 레이어 명시 |
| QA 계획에 `Manager`, `Staff` 역할 등장 | MVP 공식 역할에서 제외 | P1 권한 프리셋으로만 검토 |
| URL이 `/app/role/...`, `/app/...`, 기존 `/dashboard`로 혼재 | 최종은 `/app` 아래 모듈 중심 URL | `/app/...` 라우트 적용, 기존 플랫 라우트는 리다이렉트 |
| 핵심 화면 5개와 현재 구현 5개 화면이 다름 | 현재 구현은 프로토타입 모듈, 최종 핵심 화면은 역할별 5개 | 어드민 권한 관리, 대표 지점 대시보드, 학부모 자녀 대시보드 정교화 |
| 결제 정책에서 "납부"와 "수기 기록" 표현 혼재 | MVP는 수기 결제 기록만 제공, 온라인 납부는 제외 | 결제 CTA 문구를 "결제 상태 확인/문의"로 조정 |
| 출석 상태가 삭제된 요청 계열 값과 사유결석 값으로 혼재 | 요청 기능은 비활성화하고 출석 상태 enum은 최종 값으로 통일 | 스키마/타입 리네이밍 |
| 디자인 시스템 색상안이 두 버전 존재 | `docs/design-system.md`를 기준으로 확정 | CSS 변수와 컴포넌트에 반영 |
| `gymId`와 `branch_id` 표현 혼재 | DB/코드는 `branch_id`, UI 라벨은 지점 | 문서와 타입에서 `branch`로 통일 |

## 11. 중복 정리

## 14. 릴리즈 통과 기준

MVP는 다음 조건을 모두 만족해야 출시 가능하다.

- 총괄 어드민이 지점을 만들고 대표를 배정할 수 있다.
- 대표가 회원, 학부모, 코치, 수업, 회원권을 생성/수정할 수 있다.
- 코치가 모바일에서 수업별 출석을 30초 이내 처리할 수 있다.
- 회원/학부모가 일정, 출석, 결제 상태, 공지를 확인할 수 있다.
- 요청 기능 화면과 카드가 노출되지 않고 비활성 API가 데이터를 변경하지 않는다.
- 코치는 결제 금액을 볼 수 없고 회원권 상태만 볼 수 있다.
- 대표는 자기 지점 데이터만 볼 수 있다.
- 총괄 어드민의 전체 접근과 주요 변경은 감사 로그에 남는다.
- 지점 간 데이터가 섞이지 않는다.
- 핵심 데이터는 CSV로 내보낼 수 있다.
- 관리자, 코치, 학부모 모바일 화면에서 주요 업무가 깨지지 않는다.
- 파일럿 지점에서 최소 2주 동안 실제 출석과 결제 상태를 운영할 수 있다.
